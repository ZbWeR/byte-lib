# Catalog data

- `lib/data/catalog.json` is generated by `pnpm sync:wiki` from the UESTC Byte Lib wiki space. Do not add standalone documents there.
- `lib/data/contributions.json` is the hand-maintained list of submitted docs that are not (yet) wiki children. Each item needs `id`, `title`, `collegeSlug`; `desc` and `supplementOf` are optional.
- `lib/data/doc-desc.json` holds card blurbs for wiki-space documents. Contribution blurbs live on the contribution entry itself.
- `lib/data/catalog.ts` merges the two sources at build time. If a contribution id later appears in the wiki catalog, show it once (wiki fields win; contribution `desc` / `collegeSlug` still apply). Duplicate contribution ids or unknown `collegeSlug` fail the build.

# Preview, don't record

Do not proactively run end-to-end browser walkthroughs, computer-use sessions, or screen recordings to verify UI. These are too slow for this repo.

Only do that kind of manual GUI testing when the user explicitly asks.

After UI or routing changes, deploy a Vercel preview (`vercel deploy --temporary --yes --prod`) and give the user the preview URL plus the claim URL. Let them look at it themselves.

A local `pnpm build` / `pnpm typecheck` is enough automated verification unless they ask for more.
